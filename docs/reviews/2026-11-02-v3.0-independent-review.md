#### C1. `gate_k9` 会抛未捕获异常，且**吞掉整轮所有 findings**（`scripts/check.py:533`）

`_plot_rows` 的表头判定只保证 `"情节点"` 与 `"覆盖镜号"` 两列存在，紧接着无保护地执行 `col_st = cells.index("状态")`：

```python

    col_cov = cells.index("覆盖镜号")
```

实测：01 情节点清单表头写成 `| # | 情节点 | 覆盖镜号 |`（或把「状态」改名为「完成」）→

```
exit code: 1
stderr: ValueError: list.index(x): x not in list
```

为什么这是 Critical，而不只是「没抓到」：
- `main()` 的 gate 循环先跑完再打印（`for gate_id, gate_fn in GATES: findings.extend(...)` 之后才是 `for f in findings: print(...)`）。K9 是第 9 个门，一旦它抛异常，**K1-K8 已经收集到的 findings 全部丢失**，用户只看到一个 Python traceback。

- 硬规则 15 写「不过不进下一阶段」；一个 traceback 会直接卡死整条流程，而用户无法从中知道该改哪一行。

修法：`col_st = cells.index("状态") if "状态" in cells else -1`，状态列缺失时报一条文件级 Finding（「情节点清单缺『状态』列——K9 无法核对覆盖」）而不是崩；并在 `main()` 的 gate 循环外包 `try/except Exception` → 转成 `[Ki] 内部错误: <异常>` + exit 2，避免一个门拖垮整轮。

#### I12. K10 的 PLAN 唯一性会拦住 E2 的正常用法；`\b` 在中文后失效；REF 解析是子串包含

3. **REF 解析用子串**：`if full not in doc03`。实测 03 只登记 `REF-CHAR-SHEN-FACE` 时，04 里悬空的 `REF-CHAR-SHEN` 被判定「可解析」（因为前者包含后者）。修法：用同一正则抽取 03 的 REF id 集合做集合比。

### Minor (Nice to Have)

#### M1. K5 报错行号整体偏 1（`scripts/check.py:596`、`:631`）

`_segments_04` 返回的 `buf` **不包含** `## 段落` 那一行，而 `gate_k5` 用 `seg_line + off`；`off=0` 对应的是 `seg_line + 1`，所以每条 finding 的行号都少 1。实测 bad_peak：真实行 45/51 被报成 **44/50**。CT6 承诺「具体到文件+行号」，偏 1 会把用户指到上一行。修法：`seg_line + off + 1`。

#### M2. `scripts/check.py` 925 行，超过用户自己的 800 行上限

用户 `coding-style.md` 写「200-400 typical, 800 max」，计划的 Global Constraints 也写「单文件目标 <800 行」。Markdown 侧全部达标（screenwriting-craft 288、cinematography 393、action-combat 214、prompt-rules 608、SKILL 252、templates 631），唯独唯一的代码文件超限。可按「解析层（`_storyboard_rows`/`_plot_rows`/`_dialogue_set_01`/`_segments_04`/`_shot_blocks_04`）/ 门层 / CLI」拆成两三个文件，顺便消灭 I5 的两套解析器。

#### M3. 死代码与误导性注释

- `scripts/check.py:314-316`：空循环 `for line_no, text in _dialogue_rows_05(project): pass  # 朗读时长校验在下方按列做`——白解析一遍 05。

#### M5. `K1` 正向语境正则有一项重复交替，全角引号形态被漏掉（`scripts/check.py:223`）
