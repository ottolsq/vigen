## 1. 背景与问题

用户实际使用 vigen(V2.9)后反馈四个痛点:

1. **台词、剧情、剧本过于幼稚、拖沓**
2. **画面、分镜、运镜过于简单**——即使 vigen 已声明 40 运镜 + 8 转场,产出仍单调
3. **打斗几乎没有、无详细打斗描述;打斗剧情中慢镜头过多**
4. **每个视频片段的分镜和镜头都要用户自己调整,时间太慢**

研究结论(三组一致印证):

- vigen 的**参数层**规则(五要素运镜写法、机位数值化、秒级动作时序、武器力学表)**不弱于甚至强于** drama-skills;
- 差距集中在三处:**①内容缺失**(台词行动理论、整场打斗编排、对白场切法等 vigen 全库没有);**②规则不咬人**(库和规则存在,但缺可判定的选择机制与强制门,agent 默认走捷径);**③质量门靠用户肉眼**(vigen 的校验是写给 agent 的 prose 清单,机械错误漏到用户面前,导致逐镜人工把关)。

用户已拍板两项裁定:

- **F1**:vigen 突破"纯文档零脚本"约束,新增薄校验脚本 `check.py`(只 enforce 机械可判定的门,不查审美)。
- **F2**:删除 cinematography.md 中"最稳 5 种"说法/列表(它给 agent 发"用固定机位"的通行证)。

## 2. 目标与非目标

**目标**

- G1 剧本/台词:补齐"行动维度"生成机制(议程→策略→受阻→转向→状态变化→兑现),自检从主观问句升级为操作程序+证据引用
- G2 分镜/运镜:选择层咬人——功能决策表、条件触发门、封闭动机词表;删除逃跑通行证
- G3 打斗:补整场编排层(交手账),修复库内自相矛盾(combat 文件推慢镜),修复并行分发断链
- G4 效率:机械校验交给 check.py,用户停点收缩为"真创作分叉+批次抽查"

**非目标(本轮不做)**

- 不调用生成 API、不做剪辑执行(vigen 使用边界不变,check.py 只读项目 Markdown)
- 不引入 drama-skills 的规则四级分级制度、节奏档案/秒数阈值、生产标签体系(研究员建议不移植:vigen 两档体系够用,引入需重构全库)
- 不引入 Dashboard、不做子 skill 拆分、不建结构化项目状态机(01-06 Markdown 契约不变)
- mechanism-loop 等长线疲劳机制留待用户反馈"越写越无聊"再议

## 3. 移植纪律(全程强制)

1. **单一事实源**:每条规则只在一个文件写全文,其余"要点+指针"。实施前按 vigen learning-guide 缺陷 17 纪律 **grep 全库查重**(子代理报告称"X 不存在"必须自己核实);发现重复保留归属表的"家",其余改指针
2. **出处标注**:所有移植条目标 `[drama-skills: 文件名#节]`;由 drama-skills 机制改写(非照抄)的标 `[drama-skills 改写]`
3. **三层粒度**:规则/模板/例句,drama-skills 的弱/强对照例句逐字摘入(vigen 学习法:"样本比规则更有效")
4. **校验脚本纪律**(新增,写入 SKILL.md):check.py 只 enforce 文档已写的门;改门必同步改脚本;**误拦的门比没有门更糟——宁松勿滥,只收零歧义条款**
5. 每节一个 git commit,用户可逐节验收;learning-guide/README/create.md/吸收台账随节同步(用户全局规则:更新代码同步更新文档)
