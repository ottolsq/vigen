# 模型能力档案（仅支持能力，2026-11-03 更新）

> **确定模型时读本文件。本文件只记录各模型的支持能力**（模式/分辨率/时长/参考素材限制/参数），不记录任何"提示词癖好/最优写法"类主张——该类主张已停用归档（见 _archive-suspended-claims.md，勿读）。提示词骨架统一见 prompt-rules.md（风格1 多镜头公式），不分模型轨道。
> 更换模型时按"能力档案卡"格式追加本文件即可，提示词骨架不变。
> **能力按"模型 × 供应商（provider）"两维登记（V2.9）**：同名模型经不同供应商/网关接入时能力可能不同（实测：moma 与 apiMart 的 H3，generateAudio 一个拒一个收）——档案卡里的能力默认是官方口径，**供应商差异记入"供应商差异备忘"节**；生成前对当前接入的供应商实测探测一次关键能力（音频/参考图数/时长上限），以实测为准（SKILL.md"能力实测优先于锁定记录"的检查点化）。

## 图片模型能力

### gpt-image-2（OpenAI，2026-04）
- 模式：文生图 / 图生图 / 多图参考（多张输入图，用途靠提示词声明）
- API 内最高 2K 分辨率；宽高比最宽 3:1；宽高比直接写进提示词（如 "Aspect ratio 16:9"）
- 提示词字符上限：32,000 字符（OpenAPI 规范，适用于 GPT image 模型）
- **input_fidelity 参数**：官方口径 Image 2 **必须省略**（历史 Cookbook 编辑示例用 `input_fidelity="high"` 是旧口径，已过时）

### gpt-image-2.5（OpenAI，2026-10）
- **精确模型 ID**：`gpt-image-2.5-flare` / `gpt-image-2.5-sunburst`（另有 `-2026-09-08` 快照后缀）——**无裸 `gpt-image-2.5` 别名**；使用前控制台/API 核对确切 ID
- **两型号均支持生成+编辑**（Sunburst 不是编辑专用）：Flare=速度优先（默认档），Sunburst=质量优先（高要求场景：小字/密集信息板/近景肖像/身份敏感编辑）
- **迁移决策**：Image 2 已达标 → 先评 Flare，不达标再评 Sunburst；首次比较固定 quality、同输入，**先立质量再优化延迟**
- **quality 档位**：low / medium / high / **xhigh / max** / auto（Image 2 止于 high；xhigh/max 是显式选项不是自动升级）；小字/密集信息/肖像/身份敏感编辑用 medium/high 起步比较；low 在延迟敏感场景意外地强
- **size 输出硬约束**：边长为 16 的倍数、最长边 ≤3840、长短比 ≤3:1、总像素 655,360–8,294,400；超过 2560×1440 属实验区。常用档：1024×1536（竖）/ 1536×1024（横）/ 1024×1024（方）/ 2560×1440 / 3840×2160。快捷映射：2k=2048×2048、wide=2048×1152、tall=2160×3840、portrait=1024×1536
- **编辑输入**：1–16 张 png/webp/jpg，单张 <50MB
- **mask**：PNG、<4MB、与首图同尺寸；多图时只作用于第一张
- **markup（2.5 新增）**：透明 PNG 叠加在第一张图上引导编辑；须与首图同尺寸（含方向校正后）、含透明像素；**不能与 mask 同用**（OpenAPI 组件描述出现"2.5 and 2.6"，2.6 疑似在路上）
- **其他参数**：n=1–10（一次多图）；partial_images 0–3（流式）；background transparent 必须配 png/webp 输出（验收检查解码后 alpha 通道——"画出来的棋盘格不是透明"）；output_compression 0-100 仅 jpeg/webp；moderation auto/low 仅生成端；safety_identifier（安全监控，`user` 已弃用）；**style / response_format 对 GPT image 模型不支持**（风格写进提示词；始终返回 b64_json）；端点仍是 `/v1/images/generations` 与 `/v1/images/edits`
- **模型清单**：`gpt-image-1-mini` / `1.5` / `2` / `2-2026-04-21` / `2.5-sunburst(-2026-09-08)` / `2.5-flare(-2026-09-08)` / `chatgpt-image-latest`；**`gpt-image-1` 已于 2026-10-23 关停；DALL·E 2/3 已于 2026-05-12 退役**
- **input_fidelity**：官方 OpenAPI/SDK 仅明确 `gpt-image-1.5` 支持 `high/low`、`gpt-image-1-mini` 仅 `low`；**`gpt-image-2` 请省略**；**2.5 未列入支持名单——默认不传**。社区有"Flare 传 high 报 400、Sunburst 可能支持"的报告，官方未确认；使用前按供应商实测。
- **Sunburst 实测结论（作者 5 次全参数实测，[用户实测] 级）**：
  1. **成功出图 ≠ 内容正确——模型会自行发明规格与文案**（手表加编造参数、产品图加未批准的 "NO SUGAR"）→ **验收必查项：排查模型自加的文字/参数/品牌**（联动海报护栏文字白名单）
  2. 版式遵循是部分的（要求三层封闭楼层只出两层、指定方向的阴影画反）——参考图驱动的版式不能假定 100% 遵循，验收对照逐项核
  3. **models.list 查不到 / retrieve 404 ≠ 不可用**——元数据查询不能判定可用性，以实际生成端点响应为准

## 边界与失败模式（官方 + 实测）

- **文字渲染仍不完美**：位置/清晰度需人工核对；长段文字会糊（实测）
- **跨生成一致性有限**：角色/品牌元素无法像素级锁定
- **版式精确落位不稳**：元素精确位置可能失败
- **模型会自加内容**：规格/文案/品牌字样（Sunburst 实测）→ 验收必查
- **多轮编辑累积漂移**；mask 只是引导，**不保证像素边界**；严格保留走外部合成
- **参考图必须分工**，否则模型不知道用途；仅在文字里提"参考图"而未真传图无效
- **安全**：上游 LLM 拒绝 + 下游输入/输出双向检查；拦截 `code=moderation_blocked`（实测）；真实人物/深度伪造风险；**C2PA + SynthID 隐形水印**（截图/重编码会剥离——实测/经验；是信号不是证明）

> 事实来源（2026-11-03 核验）：ChatGPT Images 2.5 System Card（2026-09-08，deploymentsafety.openai.com PDF）、openai/openai-openapi 规范、官方 SDK 类型定义、openai-cookbook《GPT Image Generation Models Prompting Guide》（2026-04-23 Image 2 时代快照）、help.openai.com/zh-hans-cn/articles/9055440。platform.openai.com/docs/guides/image-generation 在核验时被网络策略拦截（403），上述事实取自官方 PDF/SDK/OpenAPI/Cookbook。

## 模型选择经验（[社区经验]，与官方定位一致）

- **Sunburst**：用于角色资产固化、精细修图、参考图重绘；**Flare**：用于批量草图、创意发散、低成本量产

## 不采信清单（社区说法与官方不符/未文档化——不得写入提示词规则）

- **"模型无法生成可识别文字"**：与官方 2.5 冲突——官方已改进文字渲染并给出完整写法（引号/全大写/字体层级/逐字母拼写/质量档）。按 `prompt-rules.md` 一节的官方结构块与 `realism.md` 画面文字物理化规则写
- **"2.5 官方支持 input_fidelity=high"**：官方 OpenAPI/SDK 未列入 2.5；仅社区报告（Sunburst 可能可用、Flare 报 400）。默认不传，需按供应商实测
- **"官方支持 outpainting"**：官方参数面未文档化；可通过编辑+画布外扩尝试，但不得写成官方能力

## 视频模型能力

### happyhorse-1.1-t2v / -i2v / -r2v（阿里百炼 DashScope）
- 模式：t2v（文生视频）/ i2v（首帧单图参考）/ r2v（多图参考，1-9 张）
- 时长 3-15 秒；size 写法 `1920*1080`（`1080P` 写法已废弃）；支持语言：中/英/日
- 自带音效+人物语音+口型同步（纯提示词层控制，无独立音频 API 参数）
- 异步任务轮询；720P ¥0.9/秒、1080P ¥1.2/秒

### MiniMax-H3（官方 README 一手资料，2026-10-24）

> 来源：MiniMax-AI/MiniMax-H3 官方 README（用户提供本地副本 `skills制作相关参考材料/minimax-h3-README.md`）。标注 `[官方文档]` 的条目为权威能力参数；标注 `[网关口径]` 的以实际控制台为准。

**输出规格 `[官方文档]`**：
- 时长：**4-15 秒**（旧档案"5-15"为网关口径，官方为 4-15）
- 宽高比：21:9 / 16:9 / 4:3 / 1:1 / 3:4 / 9:16（含但不限于）
- 分辨率：**短边默认 768px**；2K 需经 **H3-Regenerate-2K** 模块（768p 结果+原始上下文回灌重生成，能恢复小文字与细节——常规超分要"猜"的东西它能从上下文拿回）
- 帧率：**24 FPS**；音频：**32 kHz 立体声**（原生带声）
- 对白语言：**稳定支持 11 种**（阿拉伯/中文/英/法/德/意/日/韩/葡/俄/西），其他语言不同程度支持

**两个任务检查点 `[官方文档]`**：

| 检查点 | 输入模式 | 规格 |
| --- | --- | --- |
| **H3-Base-FL2VA** | 首尾帧模式 | 支持 **0 / 1 / 2 张输入图**：0 张=文生视频（t2va）；1 张=首帧生视频 **或** 尾帧生视频；2 张=首尾帧生视频（fl2va） |
| **H3-Base-Ref2VA** | 全参考模式（omni-reference） | **图片 ≤9 张**；**视频 ≤3 段，每段 2-15 秒，总时长 ≤15 秒**；**音频 ≤3 段，每段 2-15 秒，总时长 ≤15 秒**；混合输入文件总数 **≤12** |

> 网关（easyframe 等）可能把这些拆成 mode=t2va/i2va/fl2va/l2va/ref2va 的独立取值，并附 resolution 480p/720p、seconds 整数、model=minimax-h3-mini/-fast/-base、prompt_optimization 等参数 `[网关口径]`——以实际控制台为准；能力边界以上表官方规格为准。

**三模块架构与提示词形态（决定用哪套骨架）** `[官方文档]`：
- **H3-Context-IR**：托管的预处理/编排系统——把自由形态多模态输入（文本/图/音/视频）做指令解析、跨模态关联、时序理解、复杂逻辑推理后，**转成 H3-Base 能直接理解的结构化中间表示（Context IR）**。官方原文：**"H3-Context-IR 对最终输出质量至关重要，强烈建议纳入生成流程，或按 Prompting Guidance 自建上下文处理系统"**。未开源（多阶段+多托管模型），提供 API：`/video-generation-v2-h3-context-ir`
- **H3-Base**：吃 Context-IR 的结构化输出，产 768p 音视频（本地可部署：SGLang/vLLM/diffusers/ComfyUI；BF16；CFG 蒸馏权重）
- **H3-Regenerate-2K**：768p + 原始上下文回灌重生成 2K；API：`/video-generation-v2-regeneration`

**由此得出的提示词形态规则（关键——决定用哪套骨架）**：

| 生成路径 | 提示词形态 |
| --- | --- |
| 官方平台 API / 海螺 App / Hub（**含 Context-IR**） | **自然语言即可**——Context-IR 负责转结构化。用本 skill **骨架 A**（风格1 多镜头公式，中文自然语言） |
| 直连 H3-Base（本地部署 / 无 Context-IR 的网关） | **必须自己充当 Context-IR，写结构化中间表示**：`integrated_multimodal_description: [Shot N] … / overall_soundscape: … / non_diegetic_music: …`；Ref2VA 另加 `subject_definitions / summary / retention_analysis / detailed_description`；标签 `<Picture N>` `<Video N>` `<Audio N>` `<Subject N>` `(S1)` `<d>[语言] 台词</d>`；台词逐字保留不翻译（`<d>` 是 tokenizer 特殊 token） |

> **多帧对齐（可选，需实测）**：若供应商支持 `<Picture k>` 时间对齐，可按 prompt-rules「生成路径判定·多帧配方」把每段切点帧钉到秒；默认不假定支持，先按供应商实测（能力实测优先）。
> 官方 README 的三个可复现案例（T2VA 10s / I2VA 8s / Ref2VA 5s）给出了 H3-Context-IR 的输出全文，就是结构化形态的权威样例——走直连路径时按那些样例的字段与写法组织。旧档案中被停用的 H3 结构化语法描述因此**部分恢复为 [官方文档] 级**（见 _archive-suspended-claims.md 第五节）；仍停用的是那些无官方出处的"癖好/效果"类主张（太短是失败模式/15s 漂移/音频收敛晚等）。
> 官方 I2VA 样例的写法特征（可借鉴进骨架 A）：单段落内用 `[Shot 1]…[Shot 2] At 00:04.500, the camera cuts to…` 表达段内切镜；`overall_soundscape` 按时间顺序写声音演变（"begins with… soon drowned out by… then cuts abruptly back to…"）；`non_diegetic_music` 写乐器/速度/动态而非"悲伤的音乐"。

**安全护栏 `[官方文档]`**：提交的文本/图片/视频与增强后的提示词都会被自动审核，涉嫌违法/色情/侵权第三方权利的内容可能被拦截；官方声明存在误判（false positive/negative）可能。

**其他 `[网关口径]`**：视频留存 24h、下载 URL 1h 有效——生成后立即转存；I2VA 首帧图会被拉伸到画布（不保宽高比）、尾帧居中裁剪——参考图必须与目标画幅同比例；异步 POST /v1/videos → GET /v1/videos/{id} 轮询、240s 强制供给期限；提示词上限单文本项 7000/合计 30000；图片单张 ≤20MiB、超 8MiB 或长边超 2048px 自动缩放转 JPEG；`prompt_optimization=false` 时逐字传递（与锚定逐字原则契合）。

**请求体合计体积预算（V2.9，[用户实测]）**：参考图除了"数量上限"还有**体积维度**——实测 9 张 2K PNG 经 base64 编码后请求体 70.7MB，超过网关 64MB 上限被拒。**生成前估算**：张数 × 单张编码后体积（PNG base64 ≈ 原文件 ×1.37）> 60MB → 减张数、降分辨率（2K→1024 短边）、或转 JPEG 再挂。数量没超≠能提交，两个维度都要过。

## 语音能力

### 音频参考能力分档（音色自提取法的前提——决定 05 与 04 是否写音色参考）

| 模型 | 音频参考 | 音色一致策略 |
| --- | --- | --- |
| **happyhorse-1.1** | **无**（无独立音频 API 参数，纯提示词层控制语音） | 只靠**发声描述公式文字层**逐字复用；**不写音频参考** |
| **MiniMax-H3** | **有**（音频参考 ≤3 段，每段 2-15s） | 可走**音色参考自提取法**（见 consistency.md 四节） |
| **Seedance / 即梦系** | **有**（多模态参考，含音色/音频参考） | 可走音色参考自提取法 |

> 主栈模型：happyhorse + H3；Seedance·即梦系语法见 prompt-rules 三·五节（四括号），仅当用户实际使用该系模型时启用。
> **音频参考合计时长预算（V2.9，[用户实测]）**：H3 音频参考除了"≤3 段"还有**合计时长 ≤15s** 的硬约束（实测报错 2013 才暴露）——多角色各挂一段音色参考时，3 段 × 每段取 4-5s 已接近上限；音色参考音频先截短到 5s 内再挂（截短操作属工具层，不进 skill）。
> **项目已有音色参考资产时跳过自提取（V2.9）**：项目/画布内已存在某角色的音色参考（此前段落生成后提取的、或用户直接提供的）→ **直接复用，不走"先生成试音段"流程**——consistency 四节路线二的试音段时序只在"该角色音色参考尚不存在"时适用。生成前查 05 音色参考资产表与画布存量。

### 语音直出失败的备用链路（V2.9，[用户实测]——长旁白/台词直出失败时按序切换）

视频模型直出语音失败（不支持/被供应商拒/效果不可用）时的降级顺序：
1. **换供应商重探**：同模型不同 provider 的音频能力可能不同（见供应商差异备忘），当前 provider 拒 generateAudio ≠ 模型不支持
2. **cosyvoice 对轨**：视频端只出画面+环境音，语音独立 TTS 生成后对轨（consistency 四节路线三）
3. **长台词必拆**：单段语音受视频时长上限约束——台词朗读时长（4字/秒含标点）> 14s 的旁白/独白**必须拆成多段**分镜承载（实测：115 字旁白 ≈ 29s，超 15s 上限一倍），不许指望"一段视频塞完"；拆段后每段独立走音色一致策略

### 默认：视频模型原生语音
- 优先用视频模型自带的语音/对白生成（happyhorse 口型同步；H3 音频生成；Seedance 系原生语音）——台词直接写进视频提示词
- 生成端控制：台词内容、情绪、语速用自然语言写进提示词；BGM 关闭写"无背景音乐"
- **跨片段音色一致（用户实测方案，仅限有音频参考的模型——H3 与 Seedance·即梦系；happyhorse 无音频参考输入位，靠发声描述公式文字层锁定）**：先生成一段带该角色台词的视频片段 → 剪映中分离/提取音频 → 该音频作为此角色的**音色参考**，在后续片段生成时作为音频参考素材传入（H3 音频参考 ≤3 段）——音色由参考音频锁定，不再依赖文字描述

### 备选：cosyvoice-v3.5-flash（阿里云百炼，独立 TTS 对轨）
- 音色复刻：创建后 voice_id 长期有效，每次调用传同一 voice_id；加固定 seed 可复现
- 参考音频要求：10-20 秒（≤60s）、≤10MB、≥16kHz、无 BGM/噪声/其他人声、正常语速
- voice 绑定创建时的 target_model，不能跨模型使用
- 关键参数：format（mp3 默认）、rate 0.5-2.0、pitch 0.5-2.0、instruction ≤100 字符（仅复刻/设计音色）
- 使用场景：用户对音色一致性要求高、或视频模型直出语音效果不满意时，视频端只出画面+环境音，语音后期对轨

## 换模型指引

1. **需求问卷已问过的模型不重复问**（见 SKILL.md GATE0）；新项目模型记入 01 与 02 锚定表"目标模型"节
2. 新模型按"能力档案卡"格式追加本文件：模式清单 / 时长范围 / 分辨率与画幅 / 参考素材限制 / 关键参数 / 留存与转存要求
3. **只记支持能力，不记提示词癖好**——癖好类主张未经用户实测验证不入库（历史教训见 _archive-suspended-claims.md 头部说明）
4. 用户实测有效的写法，标注 `[用户实测]` 后写入 prompt-rules.md 对应骨架槽位
5. 本档案没有的新模型：向用户要官方能力文档（只取能力参数），提示词骨架仍用风格1 通用公式
6. **档案卡带核对纪律**：每份档案注明核对日期与来源（官方链接/README 副本）；二手转述的能力参数（社区整理的"支持/不支持"）**不直接入库**——入库前按官方文档重核（模型版本迭代快，几个月前的矩阵就过期）
7. **版本迁移"原样先测"**：已验证的提示词换模型新版本时，**原样先测一轮，只修实测出的具体失败**——不为版本号预防性重写（重写=丢掉已验证的部分，还引入新变量）
8. 能力矩阵可扩展为"模型 × 任务轴"定性五级表（Strong/Good/Conditional/Limited/依赖前端），**禁数值评分**（无依据的数字=伪精确）；当前只有主栈两款视频模型，暂不建表——扩到 ≥3 款时再建
