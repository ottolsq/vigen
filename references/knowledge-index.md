## 使用规则

1. **触发才读**：只有项目风格/需求命中上表场景时才读对应文件；未命中不读，省 token
2. **一次一读**：单个项目通常只需 1-2 个扩展文件（如漫剧项目 = expressions + 可能 ugc-realism）
3. **融入锚定**：扩展文件中的风格内容（导演风格/UGC 质感）一旦选用，其风格提示词并入 02_锚定表的风格圣经（作为扩展词条），全项目逐字复用——中途不换
4. **表情入库**：expressions.md 选定的表情词条写入 01 分镜表的"画面内容"列与 03 情景图的动作/表情描述，逐字复用保证跨镜同一表情不漂移

## 负面词适配规则（全扩展库通用）

扩展知识库来自社区实战资料，其中大量使用了**负面提示词**（"不要XX/禁止XX"）。**原则：负面清单原文必须保留在知识文件中（后续可能换用支持负面提示词的生图模型，不能全部舍弃），但使用时按目标模型适配转换**：

| 模型 | 负面词处理 |
| --- | --- |
| gpt-image-2 / 2.5 | **否定词无效**（会把被否定物画进去）——负面清单逐条转写为正向表述（"不要塑料感皮肤"→"natural skin texture with visible pores"） |
| happyhorse | 约束槽可用简短禁令（"画面严禁出现任何字幕/水印/logo"）——只放字幕/水印/logo 类，外观类负面无效 |
| MiniMax-H3 | 无 negative prompt——负面概念并入正文结尾 ban list（`Avoid AI artifacts, warped limbs...`） |
| 支持负面提示词的工具（即梦/可灵/SD 系/Midjourney --no 等） | **原负面清单直接可用**——换用这类生图模型时，知识文件中保留的原文清单就是为它们准备的 |

同理，扩展库中的 **"8K/超清/极致"类词是空话**（违反反空话规则）——引用时用具体质感词替换（胶片颗粒/皮肤纹理/材质细节），原词不照搬。
