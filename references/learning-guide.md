# 学习指导文档（Learning Guide——skill 的自我认知、缺陷清单与持续学习机制）

> **本文件的读者是执行本 skill 的 AI 代理（也包括维护它的开发者）**。三件事：①知道自己哪里不行（缺陷清单）②知道什么不该做（使用边界）③知道怎么持续变强（学习方法与吸收台账）。
> 维护规则：用户提供新学习资料、或实测反馈暴露新缺陷时，更新本文件对应节——**缺陷清单只增不删，除非实测证明已修复（修复的移入"已修复"节并标注版本与证据）**。

## 一、学习方法（强制——处理任何新学习资料时照此执行）

**学习 → 提炼 → 总结 → 积累**，四步缺一不可：

1. **学习**：通读资料原文，不跳读；区分资料类型（成品提示词=高可信样例 / 方法论=中可信框架 / 观点转述=低可信需交叉验证 / 模型能力参数=必须有官方或实测出处）
2. **提炼**：把资料拆成**可直接执行的规则/模板/例句**三层——规则（"运镜必写五要素"）、模板（骨架槽位）、例句（可逐字套用的成品写法）。**禁止笼统化**：不许总结成"要写得详细一点""注意画面质量"这类模糊结论；每条提炼必须具体到"照做就能复现"的粒度（如"贴地跟拍=高度距离地面10-15厘米+与脚步同步"，而不是"跟拍要写具体参数"）
3. **总结**：与现有规则对照——是新增（进对应 references 文件）、是修正（新材料推翻旧规则时**如实标注推翻依据**，如"动作容量随时长缩放（other5 成品修正旧规则）"）、还是冲突（无法判定时标注 `[待验证]` 并列出两种说法，首次实测后裁决）
4. **积累**：更新本文件第六节吸收台账（资料名/质量评估/吸收了哪些/未吸收哪些及原因）；关键内容深化细节后写入对应 references 文件（不是堆在本文件里——本文件只做索引与自我认知）

**质量分级标注**：吸收进 references 的规则按来源标注可信度——`[官方文档]`（模型厂商一手资料）> `[用户实测]`（用户真实生成验证过）> `[成品样例]`（优秀成品的提示词拆解）> `[社区方法论]`（无出处的经验总结，需谨慎、标待验证）。**无出处的主张不入库**（历史教训：V2.1 之前的"癖好"类调研主张真假参半，全部停用归档于 _archive-suspended-claims.md）。

## 二、当前对标标杆

**Seedance 2.5 = 当前质量最高的视频生成模型；其提示词模式 = 本 skill 视频提示词的最高质量标准。**

已按其成品资料（other5.md）落地的标准：
- 运镜物理参数级（起点锚/终点锚/高度厘米/角度度数/同步对象五要素）
- 台词三件套（音色描述+语气参数+原文）与动作交织、画外音显式标注来源
- PERFORMANCE LOCK 情绪弧线小传（弧线+演法基调+关系动力学）
- 正反打画面占位描述
- 曝光级精度（other6：《Fallen Leaves》"曝光故意压暗保住暗部，雪很亮但绝不过曝"——光线/曝光写到可执行指令而非形容词）
- 机位语义表（虫视/仰拍/平拍/俯拍/鸟瞰/荷兰角 各对应心理含义）

未落地/待观察：Seedance 四括号语法（台词{}/音乐()/音效<>/字幕【】）已按模型分列进 prompt-rules.md 三·五节——**仅当用户实际使用即梦/Seedance 系模型时启用**，当前主栈（H3 走平台/happyhorse）不用。

## 三、自身缺陷清单（诚实自曝——执行时主动规避，实测后迭代）

### 第一短板：画面/场景/构图/运镜的表现力

AI（包括执行本 skill 的代理）对画面、场景、构图、运镜的表现能力**不够强**——这是用户明确指出、且与 AI 视频生成模型的弱点同构的缺陷：
- **具体表现**：写运镜容易停在动词级（"环绕镜头"）而非参数级（"从左脚边 180 度升到腰胸高度"）；写构图容易罗列元素而非设计视觉重点的推出方式；写光线容易"柔和光线"而非"5600K 冷银月光从左侧斜上方切入，面部左亮右暗"
- **对策**：①所有运镜/构图/光线描述强制对照 cinematography.md 物理参数级例句库与 realism.md 张力四法写，禁止裸动词 ②持续收集成品提示词样本（用户提供的 other 系列）作为参照学习材料——**样本比规则更有效**，每条规则都应有成品例句支撑 ③写完后按"曝光级精度"标准自检：这句话摄影指导能直接执行吗？
- **状态**：V2.7 实质性修复——秒级动作时序（other10 范本）+FACE LOCK+环境动态层三项硬规则落地，动作与画面描述粒度问题从'依赖样本'变为'有章可循'；表现力上限仍依赖样本积累。**V2.8.1 补上"身体维度"**——原库 95 条词条全是面部，新建身体姿态库（无力/强撑/受惊静止四类全身序列）+ 生理反应库（11 条不可控证据）+ 情绪反向索引（剧本只写行为不写情绪名时的入口），全部 `[成品样例]` 附出处行号；**但词条层分布偏斜与"卑微/认命姿态无出处"仍未解决**（见缺陷 13/15）。**V3.8 补上"光线选型入口"**——cinematography 五节从 12 行词表扩为光位/光质/特效光/组合词四表，先选型再按 cinema-grade 参数级落笔（组合词未实测，见缺陷 23）

## 四、使用边界（不做什么）

1. **不执行生成**：只产提示词与项目文件，不调用生图/视频/TTS API，不做剪辑执行（06 是给用户在剪映的操作清单）
2. **不做真人拍摄指导**：所有运镜/布光描述是给 AI 模型的提示词素材，不是片场指令
3. **不自认剧本合格**：剧本必须经 GATE1.5 用户定稿——skill 的剧本自检（7 大漏洞）是辅助，不是替代用户判断
4. **不静默解决需求矛盾**：GATE0 对齐义务——矛盾/模糊/缺失先问用户，禁止自行脑补
5. **不静默降级表现力**：强调手段是稀缺品，只花在已点名峰值上（交手账★/情节点【峰】）；生成难度走可生成性改写阶梯改实现方式，不因"怕翻车"砍掉理想写法；降级只作生成失败后的回退兜底
6. **不用无出处的主张**：`[待验证]`/`[社区方法论]` 级规则要向用户声明可信度；停用主张（_archive）永不复活除非实测验证
7. **不越内容合规底线**：极端冲突按影视化替代表达（镜头语言/光影/动作张力），血腥色情直接描写不进提示词（平台审核会拦截，且 H3 官方护栏明文）
8. **不绑定具体画布软件**：只写通用操作纪律（参考图全量重连/版本账/尺寸校验），不写节点 API、不建画布同步脚本——用户后续可能更换画布，不同软件不通用（V3.9 用户裁定）

## 五、持续学习流程（用户提供新资料时）

```
收到资料 → ①按第一节四步法学习提炼（禁止笼统总结）
        → ②判断归属：新规则进对应 references 文件（提示词类→prompt-rules/运镜类→cinematography/
           图片类→realism/styles/剧本类→screenwriting-craft/模型能力→models/新领域→评估是否建新扩展文件）
        → ③与现有规则冲突时：新材料可信度更高→修正旧规则并标注依据；无法判定→标 [待验证] 双说并存
        → ④更新本文件：第六节台账加一行；若暴露新缺陷→第三节加一条
        → ⑤knowledge-index.md 同步路由（新扩展文件必须入索引表，注明"何时读"——保证按需加载不烧 token）
        → ⑥测试验证（回归测试跑相关场景）→ 提交 git（一批一提交，不混批）
```

**token 纪律（用户明确要求）**：
- 扩展知识文件**必须经 knowledge-index.md 路由按需读取**——命中场景才读，未命中不读；新文件入库时必须同步在索引表登记"何时读"的精确触发条件
- 本文件（learning-guide.md）**不进入日常项目执行链路**——只在两种情况读：①用户提供新学习资料时 ②用户问 skill 的缺陷/边界/学习状态时。Module Map 不列本文件为常规读取项
- 学习资料原文留在 `skills制作相关参考材料/` 目录，吸收后**不把原文搬进 skill**——skill 内只存提炼后的规则/模板/例句（带来源标注）

### 测试与验证纪律（回归测试/规则验证时照此执行）

1. **配对 A/B 协议**（验证某条规则是否真的有效）：每案例 ≥3 对比较；同参考/同意图/同模型/同画幅，**唯一变量=被测规则**；公平基线（不故意弱化对照组）；尽量盲评。记录 增强版胜/基线胜/平——**单张更好不算通过**，要分布性结论
2. **阈值是量出来的，不是拍的**：需要定数值门槛时（长度/雷同度/密度），先各取正反样本 5+ 个量出分布再定线（先例：正样本 218-245 字符 vs 反样本 490-514 → 定 400 上限）
3. **误拦的门比没有门更糟**：校验规则宁松勿滥——一道总把合格产出拦下的门，执行者会开始绕过所有门；可选检查一旦变严就没人再挂
4. **失败归因分类留痕**：回归测试暴露的问题按"skill 缺口/规则歧义/执行偏差/测试提示词含糊"分类后才决定改不改 skill（先例见 tests/baseline-record.md V2.1-V2.4 各批）
5. **三类证据分离**：文本行为（提示词写得对不对）/静态校验（规则过没过）/图像验收（生成结果好不好）——分开记录，互不推断；没跑生成不许用文本证据宣称"效果好"
